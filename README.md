# 1. Общая информация

## 1.1. Назначение

Objet Trouvé Archive — персональное веб-приложение для каталогизации обуви, проведения инвентаризации, управления публикациями и продажами, финансового анализа и последующей интеллектуальной оценки рыночной стоимости.

Приложение предназначено для одного владельца и не является публичным интернет-магазином.

## 1.2. Основные задачи

- Хранение полной информации об ассортименте обуви.
- Учёт нескольких одинаковых пар.
- Проведение инвентаризации и проверки состояния.
- Контроль готовности обуви к продаже.
- Управление размещением на разных площадках.
- Учёт продаж и финансовых результатов.
- Анализ эффективности продаж.
- Получение рекомендаций по стоимости обуви.
- Накопление данных для будущего ML-анализа.

## 1.3. Основные принципы

- Минимум повторного ручного ввода.
- Разделение общих характеристик и индивидуальных данных экземпляров.
- Автоматическое вычисление количества и статистики.
- Сохранение истории продаж.
- Постепенное расширение функциональности.
- Независимость базового приложения от внешних API и AI.

# 2. Структура учёта обуви

## 2.1. Двухуровневая система

Основная структура:

**Карточка товара → Физические экземпляры**

Карточка объединяет несколько одинаковых пар обуви.

Каждый экземпляр представляет собой конкретную физическую пару, которая может иметь собственные дефекты, упаковку, фотографии, цену, статус и историю продажи.

## 2.2. Общая карточка товара

Содержит:

| Поле | Описание |
|---|---|
| Инвентарный номер | Номер, закреплённый за обувью и указанный на коробке |
| Основные фотографии | Общие фотографии пары |
| Бренд | Название бренда |
| Тип | Туфли, ботинки, сапоги и т. д. |
| Размер | Размер обуви |
| Материал | Материал обуви |
| Цвет | Основной цвет |
| Категория | A / B / C |
| Закупочная стоимость | Стоимость одного экземпляра |
| Количество | Рассчитывается автоматически |

Общая карточка также имеет внутренний технический идентификатор для работы базы данных.

Инвентарный номер не зависит от наличия оригинальной коробки.

## 2.3. Физические экземпляры

Каждый экземпляр имеет:

- Автоматический уникальный ID.
- Дополнительные индивидуальные фотографии, если необходимы.
- Статус внешнего осмотра.
- Список дефектов.
- Результат проверки при ходьбе.
- Наличие и состояние оригинальной коробки.
- Тип упаковки для отправки.
- Индивидуальную цену размещения.
- Статус продажи.
- Индивидуальные публикации и историю продажи.
- Индивидуальную закупочную стоимость, если она отличается от общей.

Общие характеристики наследуются из карточки товара.

## 2.4. Количество

Количество рассчитывается автоматически по числу созданных экземпляров.

Система отдельно показывает:

- Всего экземпляров.
- В наличии.
- Забронировано.
- Продано.
- Исключено из продажи.

Продажа не уменьшает историческое общее количество экземпляров, а изменяет количество доступных для продажи.

## 2.5. Добавление одинаковых экземпляров

Пользователь может:

1. Создать карточку товара.
2. Указать первоначальное количество.
3. Автоматически создать соответствующее число экземпляров.
4. Добавлять экземпляры позже.
5. Использовать действие «Добавить ещё одну такую же».

При добавлении нового экземпляра количество увеличивается автоматически.

Общие характеристики не нужно вводить повторно.

## 2.6. Полностью одинаковые экземпляры

Если экземпляры совпадают по индивидуальным характеристикам и текущему статусу, они могут отображаться одной группой с количеством.

Например:

«Без дефектов · Оригинальная коробка · 6 500 ₽ — 5 шт.»

При появлении различий система автоматически разделяет их визуально.

Например:
- 4 экземпляра в продаже.
- 1 экземпляр продан.

При этом в базе данных каждый экземпляр сохраняет собственную идентичность.

## 2.7. Массовые действия

Для одинаковых экземпляров можно массово устанавливать:

- Цену размещения.
- Сведения об упаковке.
- Другие общие параметры.

Результаты физической проверки не должны автоматически распространяться на непроверенные экземпляры.

## 2.8. Дублирование

Предусматривается действие «Дублировать товар» для создания новой общей карточки со схожими характеристиками.

Отдельное действие «Добавить экземпляр» увеличивает количество внутри существующей карточки.

Эти операции не должны смешиваться.

# 3. Категории A/B/C

Категории отражают личную эстетическую классификацию владельца.

**A:** интересная, визуально привлекательная и необычная обувь.

**B:** обычная, базовая обувь, среди которой могут встречаться интересные экземпляры.

**C:** обувь, эстетически непривлекательная для владельца.

Особенности:

- Категория назначается общей карточке.
- Может изменяться вручную.
- Не определяет автоматически состояние обуви.
- Не определяет автоматически площадку продажи.
- Используется для фильтрации и статистики.
- Не используется в ML-оценке рыночной стоимости.

# 5. Проверка состояния

## 5.1. Принцип

Проверка выполняется отдельно для каждого физического экземпляра.

Категория A/B/C не связана с результатом проверки состояния.

## 5.2. Внешний осмотр

Статусы:

- Не проверено.
- Проверено.

## 5.3. Дефекты

Предусмотрен выбор нескольких дефектов:

- Потёртости.
- Царапины.
- Заломы материала.
- Износ подошвы.
- Износ набоек.
- Повреждения каблука.
- Повреждения стелек.
- Пятна или загрязнения.
- Повреждения фурнитуры.
- Повреждения швов и расклеивание.
- Неприятный запах.
- Другие дефекты.

Дополнительно:
- «Дефектов не обнаружено».
- Произвольный комментарий.
- Возможность изменения результатов осмотра.

«Дефектов не обнаружено» нельзя выбрать одновременно с конкретными дефектами.

## 5.4. Проверка при ходьбе

Результаты:
- Не проверено.
- Проверку прошла.
- Обнаружена проблема.

Проверка проводится для каждого экземпляра отдельно.

## 5.5. Решение по проблемной обуви

Если обнаружена проблема, пользователь выбирает:

- Решение не принято.
- Продажа с указанием дефекта.
- Исключить из продажи.

Если обнаружена проблема, влияющая на безопасность, экземпляр не признаётся готовым к продаже до устранения проблемы и успешной повторной проверки.

# 6. Упаковка

Данные об упаковке хранятся отдельно для каждого экземпляра.

## 6.1. Оригинальная коробка

- Есть, хорошее состояние.
- Есть, повреждена.
- Отсутствует.

## 6.2. Упаковка для отправки

- Оригинальная коробка.
- Другая коробка.
- Не определена.

Отдельная база пустых коробок не создаётся.

Изменение упаковки экземпляра не влияет на инвентарный номер общей карточки.

# 7. Подготовка к продаже

## 7.1. Чек-лист экземпляра

Каждый экземпляр имеет собственный чек-лист:

1. Внешний осмотр.
2. Проверка при ходьбе.
3. Подготовка фотографий.
4. Создание описания.
5. Назначение цены.
6. Размещение объявления.

Первые пять пунктов определяют готовность к публикации. Последний пункт фиксирует факт размещения.

## 7.2. Автоматизация

Автоматически отслеживаются:
- Наличие фотографий — общих или индивидуальных, если они подходят для данного экземпляра.
- Наличие описания.
- Наличие цены.
- Размещение объявления.

Внешний осмотр и проверка при ходьбе подтверждаются вручную.

## 7.3. Статусы

**Подготовка:**
- Не готова.
- Готова к публикации.
- Требует решения по проблеме.

**Продажа:**
- Не выставлена.
- В продаже.
- Забронирована.
- Продана.
- Снята с продажи.
- Исключена из продажи.

Система рассчитывает количество экземпляров в каждом состоянии и показывает соответствующие показатели в общей карточке.

Для публикации сохраняются:

- Фотографии.
- Порядок фотографий.
- Цена.
- Дата размещения.
- Ссылка.

## 8.3. Связь с экземплярами

Публикация может относиться к одному экземпляру или к нескольким экземплярам одной общей карточки, если они продаются вместе в рамках одного предложения.

Если экземпляры имеют разные дефекты или цены, система должна позволять создавать отдельные публикации.

При продаже одного экземпляра общая публикация не должна автоматически считаться завершённой, если другие экземпляры ещё доступны.

## 8.4. Хранение контента

Тексты и фотографии публикаций сохраняются как отдельные записи.

Изменение характеристик товара не должно автоматически перезаписывать ранее сохранённые посты.

## 8.5. Будущие функции

- Шаблоны для Instagram.
- Шаблоны для Telegram.
- Шаблоны для Авито.
- Различные языки описания.
- Общий раздел Publications.
- AI-генерация текстов.

Правила привлечения аудитории из Авито в Telegram исследуются отдельно, с учётом требований площадки.

# 9. Финансовый учёт

## 9.1. Закупочная стоимость

Основная закупочная стоимость задаётся для общей карточки в расчёте на один экземпляр.

При необходимости стоимость конкретного экземпляра можно изменить.

Закупочная стоимость отдельного экземпляра фиксируется в его учётных данных, чтобы последующее изменение общей цены не искажало историю прибыли.

## 9.2. Индивидуальные финансовые данные

Для каждого экземпляра сохраняются:

- Закупочная стоимость.
- Цена размещения.
- Фактическая цена продажи.
- Расходы продавца на доставку.
- Комиссия площадки.
- Дата продажи.
- Площадка продажи.

## 9.3. Финансовые показатели

**Выручка:** сумма фактических продаж без отдельно оплаченной покупателем доставки.

**Результат без учёта закупки:**

Выручка − комиссии − расходы на доставку за счёт продавца.

**Прибыль с учётом закупки:**

Выручка − закупочная стоимость проданных экземпляров − комиссии − расходы продавца на доставку.

Оба показателя доступны для отдельного экземпляра, общей карточки, категории и всего магазина.

## 9.4. Частичная продажа

Если в общей карточке пять экземпляров и один продан:

- Общее количество остаётся 5.
- Продано: 1.
- Остальные экземпляры сохраняют свои статусы.
- Финансовый результат рассчитывается только по проданному экземпляру.

## 9.5. История

Проданные экземпляры остаются в базе данных.

Доступны даты продаж, установленные цены, фактические суммы и финансовые результаты.

# 12. Price Intelligence

**Этап:** V2.

## 12.1. Назначение

Расчёт рекомендуемой цены размещения обуви на основании цен сопоставимых рыночных объявлений.

## 12.2. Источники

Гибридный подход:
- Автоматический поиск в разрешённых источниках.
- Ручное добавление аналогов.

Подходящие датасеты, API и способы сбора информации исследуются отдельно.

## 12.3. Поиск аналогов

Учитываются:
- Бренд.
- Тип.
- Материал.
- Размер.
- Цвет.
- Дефекты, если данные доступны.

Для малоизвестных брендов поиск расширяется на обувь других брендов со сходными характеристиками.

## 12.4. Оценка

Первоначально используется статистический подход:

1. Поиск аналогов.
2. Проверка релевантности.
3. Приведение цен к единой валюте.
4. Исключение неподходящих данных.
5. Расчёт медианы и ценового диапазона.
6. Предложение цены размещения.

## 12.5. Результаты

- Рекомендуемая цена.
- Диапазон.
- Список аналогов.
- Источники.
- Объяснение.
- Возможность исключать аналоги.
- Ручная корректировка цены.

## 12.6. Связь с экземплярами

Базовая оценка может рассчитываться по общим характеристикам карточки.

При назначении цены отдельному экземпляру система учитывает его индивидуальные дефекты и другие доступные характеристики.

При отсутствии достаточных данных для такой корректировки система сообщает об ограничении точности.

Результаты оценок и использованные данные сохраняются.

# 13. Machine Learning

**Этап:** V3.

## 13.1. Прогноз стоимости

Разработка и тестирование ML-модели на рыночных данных.

Возможные признаки:
- Бренд.
- Тип обуви.
- Материал.
- Размер.
- Цвет.
- Дефекты.
- Наличие оригинальной упаковки, если данные позволяют учитывать её влияние.

Состав признаков проверяется экспериментально.

Категория A/B/C в прогнозе рыночной стоимости не используется.

## 13.2. Компьютерное зрение

- Поиск визуально похожих товаров.
- Распознавание типа обуви.
- Определение цвета.
- Предположение о материале.

Результаты распознавания подтверждаются пользователем.

## 13.3. Оценка качества

Сохраняются рекомендации по цене и фактические результаты продаж.

Предусматривается возможность сравнения статистических и ML-методов.

# 17. Критерии готовности MVP

MVP считается готовым, если пользователь может:

1. Создать общую карточку товара.
2. Добавить несколько одинаковых экземпляров.
3. Увидеть автоматически рассчитанное количество.
4. Просмотреть индивидуальные данные каждого экземпляра.
5. Изменить индивидуальные дефекты, упаковку и цену.
6. Проверить экземпляры по отдельности.
7. Увидеть одинаковые экземпляры одной визуальной группой.
8. Отметить один экземпляр проданным, не затрагивая остальные.
9. Получить корректное количество доступных и проданных экземпляров.
10. Создать и сохранить публикацию с фотографиями.
11. Указать площадку и дату размещения.
12. Рассчитать результат продажи с учётом и без учёта закупки.
13. Найти товары и экземпляры через фильтры.
14. Просмотреть Dashboard.
15. Получить статистику по категориям A/B/C.
16. Повторно открыть приложение без потери сохранённых данных.

**Итоговая концепция**

Objet Trouvé Archive — персональная система управления ассортиментом обуви, в основе которой лежит двухуровневая структура: общая карточка товара и индивидуальные физические экземпляры.

Система позволяет удобно учитывать одинаковые пары, сохранять их индивидуальные особенности, контролировать продажи и постепенно расширять функциональность за счёт аналитики и машинного обучения.
